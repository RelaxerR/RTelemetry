# Безопасность

До публикации поддерживается ветка main и кандидат 1.0.0-rc.1. После выпуска
исправления безопасности получают актуальные версии 1.x.

Не включайте реальные ключи, пароли и сырые события в issue. Для уязвимостей
используйте приватный Security Advisory репозитория после включения этой функции
владельцем; до появления публичного репозитория свяжитесь с владельцем лично.

Ключ приёма в клиентском приложении не является секретом и не заменяет защиту
сервера. Админ-ключ и пароль статистики задавайте через окружение/secret store.
В production нужен HTTPS. Development-конфигурация предназначена только для
локальной разработки. Не публикуйте каталог данных и журналы с IP клиентов.

Проверка перед релизом: тесты согласия, доступ к статистике и админ-API,
лимиты приёма, зависимости (`dotnet list package --vulnerable --include-transitive`)
и отсутствие секретов в текущих файлах и истории Git.
