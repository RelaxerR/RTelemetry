# События

> Каталог событий. Стандартные события понимает любой потребитель RTelemetry, профиль
> приложения описывает его собственные события. Любое изменение формата — по правилам
> `AI_MEMORY.md`, раздел «Инварианты».

## Конверт (схема 1)

Пачка (`TelemetryBatch`):

| Поле | Тип | Смысл |
|---|---|---|
| `schemaVersion` | int | Версия формата, сейчас `1` |
| `project` | string | Код проекта на сервере (`tbg`) |
| `installId` | GUID | Случайный идентификатор установки, создаётся клиентом |
| `platform` | string | `android 10.0 phone`, `ios 17.5 tablet` и т. п. |
| `events` | массив | До 500 событий |

Событие (`TelemetryEvent`):

| Поле | Тип | Смысл |
|---|---|---|
| `id` | GUID | Уникален; для дедупликации повторной отправки |
| `name` | string | `[a-z0-9._-]`, до 64 символов, первая буква или цифра |
| `timestampUtc` | ISO 8601 | Время по часам устройства |
| `sessionId` | GUID | Сессия |
| `sequence` | int64 | Номер в сессии с 1; порядок при равном времени |
| `appVersion` | string | Версия приложения (в MAUI — `версия+сборка`) |
| `contentVersion` | string? | Версия контента |
| `props` | объект? | До 32 свойств: строка ≤ 256, число, bool, null |

Сервер добавляет `receivedAtUtc` — время приёма. Расхождение с `timestampUtc` показывает
офлайн-отправку и неверные часы устройства.

## Стандартные события

| Событие | Когда | Свойства |
|---|---|---|
| `session.start` | `StartSession()` — запуск или возврат в приложение | от приложения |
| `session.end` | `EndSession()` — уход в фон, выход | `duration_ms` + от приложения |
| `ui.click` | Любое нажатие: `Button`, `ImageButton`, `TapGestureRecognizer` (автоматически), свои контролы через `ClickTracker.TrackClick` | `element`, `element_type`, `page`, `kind` (`button`/`tap`/`custom`), для тапа `x`, `y` в долях страницы 0–1 |
| `ui.screen` | Показ страницы (вызывает приложение) | `page` |

`element` — `AutomationId`, иначе `x:Name`, иначе тип элемента. Чтобы клики читались в
статистике, важным элементам нужен осмысленный `AutomationId` (он же помогает UI-тестам).

## Профиль The Book Game (`project = tbg`)

Черновик для согласования (TheBookGame#502). Текст реплик и вариантов не передаётся —
только идентификаторы.

`contentVersion` — версия встроенной истории: коммит репозитория истории или хэш экспорта
(решить при интеграции; главное, чтобы два разных экспорта не имели одну версию).

| Событие | Когда | Свойства |
|---|---|---|
| `story.started` | Новая игра | `story_id`, `source` (`builtin`/`custom`) |
| `story.loaded` | Загрузка сохранения | `story_id`, `slot` (`auto`/`1`…`5`), `scene_id` |
| `scene.shown` | Показ сцены (контекста) | `scene_id` |
| `line.shown` | Показ реплики (переход «Далее») | `scene_id`, `line_index` |
| `choice.shown` | Показ окна выбора | `scene_id`, `choice_id`, `options` (число), `option_ids` (через запятую) |
| `choice.made` | Выбран вариант | `scene_id`, `choice_id`, `option_id`, `option_index`, `latency_ms` (от показа до выбора) |
| `episode.completed` | Достигнута команда `-End` / конец эпизода | `episode_id`, `scene_id`, `duration_ms`, `choices_made` |
| `game.saved` | Ручное или автосохранение | `slot` |
| `settings.changed` | Изменение настройки | `setting`, `value` (только перечислимые значения) |

Поверх этого автоматически идут `ui.click` и `session.*`.

Открытые вопросы:

- Что считать «эпизодом» для ВКР — главу истории или прохождение до `-End`.
- Есть ли у сцен и вариантов стабильные id, не меняющиеся при переименовании в редакторе
  (иначе сравнение версий контента сломается).
- Нужен ли `line.shown` — он даёт темп чтения, но это основной объём событий.
