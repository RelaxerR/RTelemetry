# Ручная проверка ввода перед выпуском

## Что подтверждено автоматически

- `dotnet test tests/RTelemetry.Input.Tests`: 13 тестов геометрии, ближайшего элемента,
  доступности предков, перекрытий, защиты от циклов, drag, отмены и первого пальца.
- `dotnet build src/RTelemetry.Maui`: Android, iOS, Mac Catalyst, без предупреждений.
- `dotnet build samples/RTelemetry.Sample.Maui -f net10.0-maccatalyst -p:EnableCodeSigning=false`:
  сборка приложения без подписи.

Это не подтверждает фактическую доставку аппаратных событий. Запуск через UI automation
не удалось завершить: разрешение приложения по bundle id не сработало, открытие по пути
зависало до прерывания. Цепочка «физический клик → sample → локальный сервер → dashboard»
**не проверена**. Диагностический запуск исполняемого файла 2026-10-08 не завершился
сам за 12 секунд и был остановлен по timeout; crash/error в stderr не было, только системное
сообщение UIKit про background fetch. Это не является подтверждением отображения UI.
Windows требует отдельной сборки и проверки на Windows.

## Запуск

1. `dotnet run --project src/RTelemetry.Server` (Development, localhost:5180).
2. Запустить sample из `samples/RTelemetry.Sample.Maui` в IDE или через `dotnet build -t:Run`
   с нужным `-f`. Для Android emulator задан `10.0.2.2:5180`; физическому Android/iOS
   устройству нужен адрес компьютера в локальной сети, изменяемый в `MauiProgram.cs`.
3. Открыть `http://localhost:5180/`, dev-учётные данные — из development-конфигурации.
4. Нажать Grant consent. Внизу sample — последние события. Для каждого сценария сверить
   число событий и их свойства со страницей статистики/экспортом сервера.

## Особые риски, требующие проверки на устройствах

- Windows routed PointerReleased приходит на корень после дочерних обработчиков. Для
  синхронной навигации в Clicked сохраняется неизменяемый снимок исходной страницы на
  PointerPressed; после смены страницы release классифицируется по этому снимку.
  Проверить этот сценарий на Windows и убедиться, что page остаётся исходной.
- Нативные системные picker/keyboard окна, не принадлежащие дереву MAUI, не имеют
  стабильного MAUI element id. Их внутренние клавиши не относятся к этому каталогу.
- Сложные трансформации/непрямоугольные Clip используют ограничивающий прямоугольник.
- Поддержан Toolkit Popup v2 (15.0.1 в sample); более ранний Popup v1 требует отдельной
  проверки, поскольку использует другое платформенное окно.
