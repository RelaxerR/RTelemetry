# Архитектура

## Поток данных

```
Приложение (MAUI)                         Сервер (ASP.NET Core)
┌─────────────────────────────┐           ┌──────────────────────────────┐
│ ClickTracker ──┐            │           │ POST /v1/batches             │
│ адаптер игры ──┼─► Track()  │  HTTPS    │   ключ проекта → валидация   │
│                │  (память)  │ ────────► │   → IEventStore              │
│ PeriodicTimer ─┴─► Flush ───┤  пачки    │                              │
│   ↕ state.json / queue.json │  ≤ 500    │ GET /  (Razor Pages, Basic)  │
└─────────────────────────────┘           └──────────────────────────────┘
```

## Клиент

- `Track()` только кладёт событие в список в памяти под локом: никакого ввода-вывода на клик.
- Раз в `FlushInterval` (30 с) фоновый цикл отправляет пачки по `MaxBatchSize` (200) и
  сохраняет остаток в `queue.json`. Очередь также сохраняется при `Dispose`. При падении
  процесса теряется не больше интервала.
- Результат отправки: `Accepted` — удалить; `Rejected` (4xx) — удалить с диагностикой, повтор
  не поможет; `RetryLater` (сеть, 429, 5xx) — оставить до следующего тика.
- Удаление отправленного — по `Id`: за время отправки очередь могли стереть и наполнить заново.
- Переполнение (`MaxQueuedEvents`, 20 000) отбрасывает самые старые события.
- Абстракции `ITelemetryStorage` и `ITelemetryTransport` — для тестов и других сред.

## MAUI

- `UseRTelemetry()` регистрирует клиент и `ClickTracker`, заполняет папку данных, версию и
  платформу из MAUI Essentials.
- `ClickTracker.Attach(app)` подписывается на `Application.DescendantAdded` и обходит уже
  существующее дерево. Для каждого `Button`/`ImageButton` — `Clicked`, для каждого
  `TapGestureRecognizer` — `Tapped`. Повторной подписки нет (`ConditionalWeakTable`).
- Ограничения, которые нужно проверить на устройстве: распознаватели, добавленные к уже
  показанному элементу; модальные окна и Popup; собственные контролы на `GraphicsView`
  (для них — `TrackClick`).

## Сервер

- Один процесс: Minimal API для приёма и Razor Pages для фронта.
- Проекты и ключи — в конфигурации (`RTelemetry:Projects`). Ключ лежит внутри приложения и
  секретом не является: он отсекает мусор, а не злоумышленника.
- Хранилище первой версии — JSON Lines, файл на проект и день приёма. Просто бэкапить и
  читать глазами; нет дедупликации и индексов. Переход на PostgreSQL — `docs/server.md`.
