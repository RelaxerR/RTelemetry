# Ручная проверка ввода перед выпуском

## Что подтверждено автоматически

- `dotnet test tests/RTelemetry.Input.Tests`: 37 тестов геометрии, ближайшего элемента,
  доступности предков, перекрытий, защиты от циклов, drag, отмены, первого пальца,
  таксономии интерактивности и валидности опций.
- `dotnet build src/RTelemetry.Maui`: Android, iOS, Mac Catalyst, без предупреждений.
- `dotnet build samples/RTelemetry.Sample.Maui -f net10.0-maccatalyst -p:EnableCodeSigning=false`:
  сборка приложения без подписи.

Это не подтверждает фактическую доставку аппаратных событий. Запуск через UI automation
не удалось завершить: разрешение приложения по bundle id не сработало, открытие по пути
зависало до прерывания. Цепочка «физический клик → sample → локальный сервер → dashboard»
**не проверена**. Диагностический запуск исполняемого файла 2026-10-08 не завершился
сам за 12 секунд и был остановлен по timeout; crash/error в stderr не было, только системное
сообщение UIKit про background fetch. Это не является подтверждением отображения UI.
Windows требует отдельной сборки и проверки на Windows.

## Запуск

1. `dotnet run --project src/RTelemetry.Server` (Development, localhost:5180).
2. Запустить sample из `samples/RTelemetry.Sample.Maui` в IDE или через `dotnet build -t:Run`
   с нужным `-f`. Для Android emulator задан `10.0.2.2:5180`; физическому Android/iOS
   устройству нужен адрес компьютера в локальной сети, изменяемый в `MauiProgram.cs`.
3. Открыть `http://localhost:5180/`, dev-учётные данные — из development-конфигурации.
4. Нажать Grant consent. Внизу sample — последние события. Для каждого сценария сверить
   число событий и их свойства со страницей статистики/экспортом сервера.

## Android: отдельный APK для ручной проверки

Для установки через ADB соберите Debug APK со встроенными сборками .NET:

```bash
dotnet build samples/RTelemetry.Sample.Maui -f net10.0-android \
  -p:RTelemetryMauiTargetFrameworks=net10.0-android -p:EmbedAssembliesIntoApk=true
adb devices -l
adb -s emulator-5554 install samples/RTelemetry.Sample.Maui/bin/Debug/net10.0-android/com.companyname.rtelemetry.sample.maui-Signed.apk
```

Подставьте серийный номер из `adb devices -l`. Sample обращается к локальному серверу через
`10.0.2.2:5180`. Перед запуском sample проверьте, что сервер слушает порт 5180 на компьютере.
Для одного прохода запишите платформу, API, коммит sample, число ожидаемых `ui.click` и
`ui.miss` и сверку с dashboard и CSV. Используйте только синтетические события в локальном
проекте.

16.11.2026, `00f73fd`: Debug APK собран без ошибок и предупреждений. В ZIP подтверждены
сборки RTelemetry для arm64. Android Emulator 37.1.11, API 36 (arm64), на macOS завершился
с `SIGILL` до загрузки.

- После согласия получены 4 `ui.click` по `button` (один с `long_press=true`) и 2 `ui.miss`

Это проверка основной цепочки. Расширенная матрица ниже остаётся в [#10](https://github.com/RelaxerR/RTelemetry/issues/10).

## Матрица: повторить на Mac Catalyst, Android, iOS и Windows

- [ ] До согласия: 20 нажатий, пустая очередь/сеть/лента. После отзыва то же; очередь стерта.
- [ ] Button, ImageButton, TapGestureRecognizer, CheckBox, Switch, RadioButton:
  ровно один `ui.click` на физическое касание, штатное действие контрола сохраняется.
- [ ] Slider, Stepper, Picker, DatePicker, TimePicker, Entry, Editor: касание даёт один
  click; вводимые тексты и Placeholder отсутствуют в payload.
- [ ] CollectionView/ListView: касание существующего item — click; пустая область списка —
  miss; прокрутка и drag — ни одного события. Проверить повторный выбор того же item.
- [ ] GraphicsView с `RTelemetry.IsInteractive=true`: click, без marker — miss.
- [ ] Пустой фон, Label и Image — miss; `nearest_element`/`nearest_distance` соответствуют
  ближайшему видимому интерактивному элементу, за пределами scroll viewport элементы не учитываются.
- [ ] Disabled target — miss + `disabled_target=true`; скрытый элемент с сохраненной геометрией
  также miss. У скрытых элементов без layout bounds геометрическое попадание определить нельзя.
- [ ] Длинное нажатие — одно событие с `long_press=true`; drag, вернувшийся к началу, не click.
- [ ] Два пальца: только первый; отпускание второго не завершает первый; cancel не даёт событие.
- [ ] Modal и CommunityToolkit.Maui 15 Popup: page и координаты относятся к верхней странице;
  Popup button — click, фон — miss, нижняя страница не участвует в nearest.
- [ ] ZIndex, перекрытие, поворот устройства, изменение размера окна, прокрутка:
  координаты 0–1 соответствуют странице, nearest distance нормирована по диагонали.
- [ ] Уход в фон завершает сессию и сохраняет/отправляет очередь; короткий возврат сохраняет
  sessionId; после SessionTimeout создаётся новый. Проверить Apple UIScene и несколько окон.
- [ ] Выход из сети, повторный запуск и возврат сети не мешают интерфейсу.
- [ ] `AutomationId → x:Name/StyleId → тип` не содержит Text. MAUI записывает x:Name в StyleId.

## Особые риски, требующие проверки на устройствах

- Windows routed PointerReleased приходит на корень после дочерних обработчиков. Для
  синхронной навигации в Clicked сохраняется неизменяемый снимок исходной страницы на
  PointerPressed; после смены страницы release классифицируется по этому снимку.
  Проверить этот сценарий на Windows и убедиться, что page остаётся исходной.
- Нативные системные picker/keyboard окна, не принадлежащие дереву MAUI, не имеют
  стабильного MAUI element id. Их внутренние клавиши не относятся к этому каталогу.
- Сложные трансформации/непрямоугольные Clip используют ограничивающий прямоугольник.
- Поддержан Toolkit Popup v2 (15.0.1 в sample); более ранний Popup v1 требует отдельной
  проверки, поскольку использует другое платформенное окно.

### Исправление CSV по #30

Разделители записей в экспортёре приведены к CRLF независимо от ОС. Заголовок и записи
используют одинаковый разделитель. Регрессионная проверка охватывает пустой экспорт и три
события, порядок, кавычки, запятые и переносы внутри полей без нормализации исходного CSV.
Результат ручной проверки 23 ноября выше относится к версии до исправления.
